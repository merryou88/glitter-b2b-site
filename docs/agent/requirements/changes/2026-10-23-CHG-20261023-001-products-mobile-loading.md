# 产品目录移动端加载优化

## 变更原因
用户反馈 `/products/` 手机打开较慢，要求优化打开速度。

## 变更前
18 张目录主图共 2,751,250 字节，直接使用 522–1600px 原图；所有图片（包含首卡）均懒加载。线上 HTML 引用两个阻塞样式文件，既有构建脚本仅内联首页样式。

## 变更后
- 使用现有 `astro:assets` 生成 360/540/720px WebP，质量 72；候选宽度不超过原图，522px 源图使用 360/522px。通过 `srcset/sizes` 适配容器和像素密度，无新增依赖、不覆盖详情页原图。
- 仅导入符合目录首图命名约定的 `main/*-main-1.webp`，避免将整套图库重复导入；非约定文件保留原图回退及加载失败占位。
- 首卡在 head 使用响应式预加载，图片 eager/high；其余卡片保留懒加载。
- 扩展现有构建脚本，为目录页内联本地 CSS，消除两次阻塞样式请求；首页原有内联及统计逻辑保留，其余页面继续使用外部 CSS。

## 验收条件
目录全部 18 张主图均输出响应式候选；预加载与实际首图候选一致，无首图重复下载；目录生产 HTML 无外部 stylesheet；375/390/768/1024/1440px 无横向溢出，移动默认 Dancewear/Swimwear 切换、桌面搜索及排序、quote/sample 弹窗正常。

## 影响范围与兼容性
只修改目录图片输出及构建后样式处理。保留产品文案、18 个产品及默认推荐顺序、筛选语义、RFQ 流程、SEO 内容、无 JavaScript 链接回退和产品详情原图。更新 REQ-SHELL-029，承接旧记录的首页及统计规则，并扩展目录样式内联范围。

## 实现位置
`src/pages/products.astro`、`scripts/inline-home-styles.mjs`。

## 验证结果
- `npm run build`：通过；18 个公开产品、59 个 HTML 页面、56 个 sitemap URL 及内部链接校验通过。
- 本机 Chrome 验证 375/390/768/1024/1440px 的布局和上述交互，无页面 JavaScript 错误。
- 在相同本地服务重放线上 HTML 与优化产物，390×844、DPR 2、150ms 延迟、200,000 B/s 下行、CPU 4 倍节流、禁用缓存，各三次。LCP 中位数 2552ms → 1236ms（约下降 52%）；FCP 中位数 668ms → 268ms。初次加载的三张产品图合计 469,948 → 156,640 字节（约减少 67%）。首卡实际请求一次，88,120 → 57,574 字节；两版首图顶部均为 392.7px。
- 线上 HTML 含 Cloudflare 注入的 email-decode 脚本，本地重放该 CDN 专用路径为 404；优化产物无本地资源缺失。模拟结果用于比较静态资源与加载策略，不能当作线上 Lighthouse 得分或用户真实地区速度。
- 未提交、未部署；发布后需在目标地区与同一移动节流条件下复测。

## 来源
用户当前关于产品目录移动端打开速度的反馈。
