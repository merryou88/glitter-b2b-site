# Retired Application URLs Return 404

## 变更原因
用户确认鞋材和手袋两个已退出经营方向的旧应用URL，不应继续重定向到不相关的舞台服应用页面，应由站点返回404。

## 变更前
以下不带尾斜杠的旧应用地址301到 `/applications/foil-fabric-for-stage-costumes/`：

- `/applications/glitter-fabric-for-shoes`
- `/applications/glitter-fabric-for-handbags`

## 变更后
删除上述两条301规则。当前应用数据不生成对应静态页面，因此带斜杠和不带斜杠的旧地址均由现有站点404页面处理。

## 验收条件
- `_redirects` 不再包含上述两个旧应用地址。
- 构建产物不生成上述两个应用详情页。
- sitemap不包含上述两个应用URL。
- 构建产物不存在指向上述两个应用地址的公开链接。
- 当前5个公开应用详情页仍正常生成。
- `npm run build` 和 `git diff --check` 通过。

## 影响范围
只改变两个已退出应用旧URL的响应方式，不改变当前应用页面、产品页面或其他重定向。

## 兼容性
旧外部链接将进入品牌404页面，不再被送到不相关的舞台服页面。Google后续抓取时会将这些URL归类为未找到。

## 实现位置
- `public/_redirects`
- `docs/agent/requirements/current/site-shell.md`
- `docs/agent/requirements/INDEX.md`

## 验证结果
- 通过：`npm run build`，共生成 41 个页面。
- 通过：`npm run validate:products`，11 个公开产品全部通过校验。
- 通过：两个旧应用地址均已从 `_redirects` 删除。
- 通过：构建产物未生成两个旧应用详情页。
- 通过：sitemap不包含两个旧应用URL。
- 通过：公开HTML中不存在指向两个旧应用地址的链接。
- 通过：当前5个公开应用详情页正常生成。
- 通过：`git diff --check`。

## 来源
用户明确要求两个旧应用地址转到404。
